HealTrip · Patient Decision Assistant

How this works, and why it's built this way

A short summary of the system: a patient describes a symptom, and the assistant tells them what to do next — see a specific kind of doctor, book something routine, or go to the ER — using real doctors and hospitals, never made-up ones.

Why this architecture

The core rule behind every decision here: the AI talks, the code decides. The model is good at understanding what a patient says and explaining things back clearly — so that's its only job. Anything that could actually hurt someone if it's wrong — how urgent a symptom is, which specialist fits, which doctor is real — is handled by plain, ordinary code instead, not by asking the AI to be careful.

The benefit

The AI can't invent a doctor, a fee, or a wrong emergency call — not because it's told not to, but because it's never given a way to state those facts itself. It can only point at real data, which is checked before anything is shown. And because the safety checks are in code, they still work even if the AI is slow, rate-limited, or completely down.

A closer look, step by step

Stages — what each one is for

  • Intake — asks what's needed before anything else happens.
  • Triage — decides how urgent it is, using fixed rules, not the AI's opinion.
  • Routing — looks up the right specialist from a table, never a guess.
  • Matching — searches real doctors that fit.
  • Drilldown — answers follow-up questions about them.
  • Emergency — a fixed safe message + nearest ER, skipping the AI entirely.
  • Handoff — confirms the choice and hands off to a human.
  • Out of scope — says plainly it can't help with that, and routes to a human.

Tools — what each one does

  • record_case_facts — saves what the patient said.
  • assess_urgency — runs the urgency rules.
  • map_symptoms_to_specialties — finds the right specialist.
  • search_providers — finds matching real doctors.
  • get_provider_details — full detail on one doctor.
  • find_emergency_facilities — nearest real ERs.
  • explain_pathway — pre-written answers to common questions.

How it avoids making things up

The AI can only ever refer to a doctor, hospital, or specialist by its ID — never by writing out a name, fee, or address itself. Before anything is shown to the patient, every ID it mentioned is checked against what a real lookup actually returned that turn. If something doesn't check out, the reply is rejected and retried once — and if that still fails, the assistant falls back to a short, honest message instead of showing something wrong.

ملخص قصير للنظام: يصف المريض عرضًا يعاني منه، فيخبره المساعد بالخطوة التالية — زيارة طبيب مختص معيّن، حجز موعد روتيني، أو التوجه إلى الطوارئ — باستخدام أطباء ومستشفيات حقيقيين، وليس أسماء مُختلقة أبدًا.

لماذا هذا التصميم المعماري

القاعدة الأساسية وراء كل قرار هنا: الذكاء الاصطناعي يتحدث، والكود هو من يقرر. النموذج جيد في فهم ما يقوله المريض وشرح الأمور له بوضوح — لذا هذه مهمته الوحيدة. أما أي شيء قد يضر بشخص فعليًا إذا كان خاطئًا — مثل درجة خطورة العرض، أو الأخصائي المناسب، أو كون الطبيب حقيقيًا فعلاً — فيُدار بكود برمجي عادي وواضح، بدلاً من الاعتماد على "حذر" الذكاء الاصطناعي.

الفائدة

لا يستطيع الذكاء الاصطناعي اختلاق طبيب أو رسوم أو تحديد خاطئ لحالة طارئة — ليس لأنه يُطلب منه عدم ذلك، بل لأنه لا يملك أصلاً وسيلة لذكر هذه الحقائق بنفسه. كل ما يستطيعه هو الإشارة إلى بيانات حقيقية يتم التحقق منها قبل عرض أي شيء. ولأن فحوصات الأمان مكتوبة في الكود، فهي تستمر بالعمل حتى لو كان الذكاء الاصطناعي بطيئًا أو محدود الاستخدام أو متوقفًا تمامًا.

نظرة أقرب، خطوة بخطوة

المسار نفسه، مع إظهار كل وحدة فعلية ومصدر البيانات الحقيقي.

المراحل — الغرض من كل مرحلة

  • الاستقبال (Intake) — يسأل عمّا هو ضروري قبل أي خطوة أخرى.
  • الفرز (Triage) — يحدد درجة الخطورة باستخدام قواعد ثابتة، لا برأي الذكاء الاصطناعي.
  • التوجيه (Routing) — يبحث عن الأخصائي المناسب من جدول بيانات، وليس تخمينًا.
  • المطابقة (Matching) — يبحث عن أطباء حقيقيين مناسبين.
  • التفاصيل (Drilldown) — يجيب عن أسئلة إضافية بخصوصهم.
  • الطوارئ (Emergency) — رسالة آمنة ثابتة + أقرب قسم طوارئ، متجاوزًا الذكاء الاصطناعي بالكامل.
  • التسليم (Handoff) — يؤكد الاختيار ويُحيل المحادثة إلى إنسان.
  • خارج النطاق (Out of scope) — يوضح بصراحة أنه لا يستطيع المساعدة، ويُحيل إلى إنسان.

الأدوات — وظيفة كل أداة

  • record_case_facts — يحفظ ما قاله المريض.
  • assess_urgency — يُشغّل قواعد تحديد الخطورة.
  • map_symptoms_to_specialties — يحدد الأخصائي المناسب.
  • search_providers — يبحث عن أطباء حقيقيين مطابقين.
  • get_provider_details — تفاصيل كاملة عن طبيب واحد.
  • find_emergency_facilities — أقرب أقسام طوارئ حقيقية.
  • explain_pathway — إجابات مُعدّة مسبقًا للأسئلة الشائعة.

كيف يتجنب اختلاق المعلومات

لا يستطيع الذكاء الاصطناعي الإشارة إلى طبيب أو مستشفى أو أخصائي إلا عبر معرّفه (ID) — لا يكتب أبدًا اسمًا أو رسومًا أو عنوانًا بنفسه. قبل عرض أي شيء على المريض، يتم التحقق من كل معرّف ذكره مقابل ما أعادته عملية بحث حقيقية فعلاً في هذا الدور. وإذا لم يتطابق شيء، تُرفض الإجابة وتُعاد المحاولة مرة واحدة — وإذا فشلت مجددًا، يلجأ المساعد إلى رسالة قصيرة وصادقة بدلاً من عرض معلومة خاطئة.
